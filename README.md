# Research Agent Project

This project is an AI-powered research assistant starter that accepts a research topic, searches for related papers, extracts structured notes from retrieved metadata, and generates a literature-review style report.

## Project Goal
The system is designed to behave like a junior research assistant:
1. Understand a topic.
2. Generate research tasks.
3. Search for relevant literature.
4. Read and summarize paper metadata/abstracts.
5. Compare findings and identify research gaps.
6. Produce a structured report with references.

This repository now reflects Phase 2 roadmap work: the system is moving from simple retrieval-and-summary into a more intent-aware, concept-preserving research assistant with relevance filtering and source validation.

---

## What the project does
- Accepts a research topic from the user.
- Uses the planner/search/reader/writer flow to generate a structured report.
- Provides a simple HTML interface for topic input and report display.
- Uses real search metadata from arXiv and Crossref when available.
- Includes a lightweight in-memory memory store for context tracking.

## File-by-file explanation

### 1. app.py
Purpose:
- Main application entry point.
- Orchestrates the full research-agent workflow.

What it does:
- Calls the planner to generate tasks.
- Calls the search agent to find papers.
- Calls the reader agent to summarize the retrieved metadata.
- Calls the critic agent for validation notes.
- Updates the memory manager.
- Passes everything into the writer to produce the final report.

Why it matters:
- This is the central controller for the project.

### 2. server.py
Purpose:
- Starts the local web server for the HTML interface.

What it does:
- Serves the page at http://127.0.0.1:8000/.
- Accepts POST requests at /generate.
- Uses the existing report-generation logic from app.py to return the report as JSON.

Why it matters:
- This file makes the project usable through a browser.

### 3. index.html
Purpose:
- Front-end user interface.

What it does:
- Provides a text input bar for the research topic.
- Contains a Generate report button.
- Sends the input to the server.
- Displays the generated report on the screen.

Why it matters:
- This is the user-facing interface for non-technical users.

### 4. agents/planner.py
Purpose:
- Creates the research plan.

What it does:
- Splits the user topic into a list of research tasks.

Why it matters:
- This reflects the planner agent part of the architecture.

### 5. agents/search_agent.py
Purpose:
- Retrieves candidate papers for the given topic.

What it does:
- Uses arXiv API and Crossref API to fetch paper metadata.
- Falls back to deterministic placeholder metadata if live APIs are unavailable.

Why it matters:
- This is the retrieval layer for the research workflow.

### 6. agents/reader_agent.py
Purpose:
- Turns raw metadata into structured notes.

What it does:
- Converts each paper’s title, authors, year, DOI, and abstract into a structured summary.
- Adds fields such as objective, methodology, limitations, and citation strings.

Why it matters:
- This simulates the reader agent stage of the system.

### 7. agents/critic_agent.py
Purpose:
- Provides validation and quality signals.

What it does:
- Produces confidence metadata such as faithfulness, citation accuracy, and hallucination risk.

Why it matters:
- This supports the evaluation and validation side of the system.

### 8. agents/writer_agent.py
Purpose:
- Generates the final report.

What it does:
- Writes a structured report including background, highlights, key papers, findings, gaps, future directions, references, and memory snapshot.

Why it matters:
- This is the report-generation module for the final output.

### 9. agents/memory_manager.py
Purpose:
- Stores the workflow state in memory.

What it does:
- Keeps a history of topics, findings, and tasks.
- Provides a simple snapshot for the final report.

Why it matters:
- This is the foundation for the memory layer described in the roadmap.

### 10. tools/search_tool.py
Purpose:
- Placeholder service for future search integrations.

What it does:
- Provides a simple wrapper that returns public sources for a research topic.

### 11. tools/pdf_reader.py
Purpose:
- Placeholder for PDF extraction.

What it does:
- Provides a stub function for future PDF ingestion.

### 12. tests/test_app.py
Purpose:
- Verifies the report-generation logic.

What it does:
- Ensures the generated report includes required sections.

### 13. data/sample_topics.txt
Purpose:
- Stores example topics for testing or demos.

### 14. reports/sample_report.md
Purpose:
- Example output file generated by the project.

## Recent Phase 2 improvements
The project now includes the main roadmap upgrades for the next research-agent milestone:
- Structured intent understanding and query-type classification for arbitrary research topics.
- Multi-query retrieval that expands the candidate pool from the original topic and its subdomains.
- Concept-preserving phrase extraction so multi-word scientific terms such as “Gaussian Boson Sampling” remain intact.
- Relevance filtering to reduce semantic drift and reject weakly related papers before synthesis.
- Source validation to reject placeholder or malformed metadata and avoid fabricated references.
- A safer report path that reports “Insufficient literature found” when no valid source-backed papers are available.

## Current limitations
This is now a Phase 2-style prototype, but several roadmap items are still future work:
- It still relies on paper metadata and abstracts rather than full PDF text.
- It uses live APIs when available, but real document ingestion and deeper citation grounding are still next steps.
- It does not yet implement full long-term vector memory or full multi-agent orchestration.
